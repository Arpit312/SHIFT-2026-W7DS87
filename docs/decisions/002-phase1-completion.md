# ChargeNOC Phase 1 Report

## Implemented Features
1. **Frontend Architecture**: Next.js 15 App Router, Tailwind v4 (CSS-based design tokens), TypeScript, React Query.
2. **Design System**: Comprehensive shared components (`Card`, `Button`, `Table`, `Timeline`, `Stepper`, `FileDropzone`, `StatusBadge`, `SeverityBadge`, etc.) adhering to the black/orange/gold professional theme.
3. **Landing Page**: Built with an expressive (but performant) Three.js abstract node animation, addressing RWA concerns, detailing the workflow, and providing transparency statements.
4. **Authentication**: Supabase Auth (email/password) integrated with PKCE flow in Next.js middleware, plus a custom registration page for EV Owners that fetches available societies.
5. **Routing & Role Guards**: Middleware token refresh and client-side `RoleGuard` wrapper ensuring users can only access their designated dashboard (e.g., `/dashboard/owner`, `/dashboard/rwa`).
6. **EV Owner Dashboard**:
   - **Overview**: Stats, active request status, next slots, latest bills, and activity timeline.
   - **New Request Wizard**: Multi-step form capturing vehicle details, photo evidence (direct to Supabase Storage), and site questionnaire. Submits request and triggers AI Photo Check.
   - **Request Tracker**: Visual timeline reflecting explicit backend state machine transitions.
   - **Photo Check Report**: Detailed UI rendering the mock AI assessment (overall verdict, confidence, safety findings, severity, and limitations).
   - **Evidence Locker**: Table view of original photos and corrective evidence.
   - **Conditions**: Tracker for pending/resolved conditions with the ability to upload proof directly to Supabase and submit it for verification.
   - **Slots & Bills**: Read-only tables for scheduling and billing cycles (Phase 1 demo state).
   - **Haan Packet**: UI to generate and download the versioned PDF.
   - **Learn & Profile**: Lightweight safety guidance, vehicle list, and data deletion request action.
7. **Role Shells**: Empty state / read-only list shells for RWA Admins, Electricians, and Super Admins.
8. **Backend API**: Django + DRF backend enforcing state machines, appending-only event logs, permissions, and exposing a MockPhotoCheckService and PDF ReportLab generator.

## API Contracts & AI Integration
- The exact `Assessment` schema proposed in the prompt was mirrored in `frontend/src/types/index.ts` and `backend/assessments/models.py`.
- The `PhotoCheckService` protocol was created, and `MockPhotoCheckService` is wired up to return deterministic demo responses based on the request.
- The `api-client.ts` cleanly wraps fetch and injects the Supabase JWT for backend HS256 verification.

## Assumptions Made
- **Next.js & Tailwind**: Used Next.js 15 with Tailwind v4 (which uses `@theme` in CSS rather than `tailwind.config.ts`).
- **Python Version**: Pinned to 3.12+ in instructions and requirements.
- **Request IDs**: Defaulted to `REQ-YYYY-NNNNNN` generated by the database.
- **Image Uploads**: Uploaded directly from the browser to a Supabase bucket (`chargenoc-evidence`) to save backend bandwidth, with metadata registered via Django API.
- **Supabase Authentication**: Standard email/password flow; `user_metadata` passes signup data to Django (Django must map this or create the Profile on first login/webhook).
- **Mobile Breakpoint**: `lg` (1024px) triggers the mobile drawer sidebar.
- **Toast Library**: Hand-rolled a lightweight Context/Portal-based toast system to minimize dependencies, since no specific library was enforced.
